# 回路図レビューアプリケーション 要件定義書

| 項目 | 内容 |
|---|---|
| 版 | 1.2 |
| 作成日 | 2026-11-21 |
| 改訂日 | 2026-11-22 |

本書は単独で利用できる。本書の内容だけで、要件の意図と判断の根拠を読み取れるように記述する。

---

## 1. 目的

回路図を入力として、設計の正しさを評価する React アプリケーションを作成する。利用者は次の 3 観点から評価を選ぶ。

- 設計レビュー: 設計通りに動作しない箇所を見つけ、修正案を提示する。
- FMEA: 指定した部品の故障が回路に与える影響を評価する。
- FTA: 指定した部品の故障の組合せから、トップ事象の原因を分析する。

## 2. 対象範囲

### 2.1 対象
- アナログ回路（線形素子と理想オペアンプを中心とする）
- 回路の入力は、手入力によるネットリストの作成を基本とする。画像からの抽出は、利用者本人の Claude Code による手動連携で行う（FR-EX-01）
- 評価に使うネットリストは、利用者が確認・修正して確定したものに限る
- 想定する利用者は設計者とする。レビュー担当向けの機能は後続とする

### 2.2 対象外（初版）
- 非線形素子（ダイオード、トランジスタ、MOSFET）
- 過渡解析、周波数掃引、ノイズ、温度特性
- 理想オペアンプ以外のモデル（実オペアンプの飽和・帯域の厳密な扱い）
- 理想オペアンプ以外の従属電源
- 部品公差の考慮

## 3. 用語

| 用語 | 定義 |
|---|---|
| ネットリスト | 部品、端子、ノード（接続点）の対応を表すデータ。JSON で保持する |
| ノード | 同じ電位になる端子の集まり（接続点） |
| MNA | 修正節点解析（Modified Nodal Analysis）。回路方程式を立てて解く方法 |
| 期待値 | 注釈（例: 「5 Vrms」）から得られる、期待される動作の値 |
| 許容誤差 | 実測値と期待値の差を、不一致と判定する限界（相対誤差） |
| RPN | リスク優先数。FMEA で S（重大度）× O（発生度）× D（検出度）として求める |
| 最小カットセット | トップ事象を起こす、故障の最小の組合せ |
| 実効値（Vrms） | 正弦波の二乗平均平方根。入力と出力の表記に用いる |
| 理想オペアンプ | 入力端子間の電圧差がゼロ、入力電流がゼロの増幅器として扱うモデル |

## 4. 基本方針

- **REQ-P-01 正しさの判断の前提**: 判断は、入力された情報（部品値、ブロック名、注釈、期待値）だけから行う。外部の仕様書は入力しない。理由: 入力情報だけで判断の根拠を明示できるため。
- **REQ-P-02 判断材料の不足**: 判定に必要な情報が不足する場合は、判定を保留して利用者に質問する。回答がない項目は「未確定」と表示する。理由: 推測による誤判定を防ぐため。
- **REQ-P-03 注釈は仕様**: 注釈（例: ゲインの記載、期待値の記載）は、期待動作として評価対象に含める。
- **REQ-P-04 免責**: 評価結果は設計支援であり、安全認証や規格適合の判定ではない。

## 5. 機能要件

### 5.1 入力（FR-IN）

| ID | 要件 |
|---|---|
| FR-IN-01 | 利用者は、画像ファイルを指定のドロップゾーンへドラッグ&ドロップして入力できる |
| FR-IN-02 | 対応形式は PNG と JPG とする。SVG と PDF は後続とする |
| FR-IN-03 | 画像は 10 MB 以下、長辺 4000 px 以下とする。複数ページは扱わず、1 画像を 1 回路とする |
| FR-IN-04 | 画像を入力した後、手入力で、または画像を参照して、ネットリストを作成する |

#### 抽出（FR-EX）

| ID | 要件 |
|---|---|
| FR-EX-01 | 画像から部品、接続、ノード、注釈を読み取る作業は、利用者本人のサブスクリプションによる Claude Code で行う（外部 AI への送信は利用者の操作で行う）。アプリは、画像と抽出の依頼内容をプロジェクトファイル（JSON、FR-ST-03 の形式）として書き出し、利用者が Claude Code から得た結果を読み込めるようにする。アプリ自身は外部 API を呼ばない。送信前に、回路図が外部の AI に送られる旨を画面に表示する |
| FR-EX-02 | 抽出結果は、利用者が確認・修正してから評価に使う。確認・修正画面を評価の必須のゲートとする |

### 5.2 確認・修正画面（FR-CK）

| ID | 要件 |
|---|---|
| FR-CK-01 | 入力画像に、部品の枠、部品 ID、ノードを重ねて表示する。重ね表示の濃さを変えられる |
| FR-CK-02 | 部品表（ID、種別、値、単位、接続、所属ブロック、状態）、ノード表（ノード ID と接続する端子）、注釈・ブロック欄を表示する |
| FR-CK-03 | 画像上の枠と表の行は、相互に選択できる |
| FR-CK-04 | 次の編集ができる: 部品の追加・削除・種別変更、値の数値と単位の分離入力（接頭辞 p n µ m k M G、単位 Ω F H V A）、元の表記の保持、信号源の種類指定（交流の実効値、交流のピーク、直流）、端子ごとのノード選択（新規ノードの作成を含む）、注釈と対象（ノード・ブロック・部品）の編集、取り消し・やり直し |
| FR-CK-05 | 確定前に検査する。**エラー**（確定不可）: 値の未読取または数値化不能、端子の未接続、部品 ID の重複、種別と端子数の不一致、接地（GND）の欠如。**警告**（確定可）: 端子が 1 つだけのノード、注釈の対象が見つからない、不確かとして示された項目 |
| FR-CK-06 | 未読取の値は空欄とエラーで表示し、利用者が入力するまで確定できない。判断材料の不足として FR-QA の質問に登録する |
| FR-CK-07 | 「確定」で、版番号を付けたネットリストを保存し、観点の選択へ進む |
| FR-CK-08 | 確定後に編集した場合、既存の評価結果を無効とし、再評価を求める |

### 5.3 判断材料の質問（FR-QA）

| ID | 要件 |
|---|---|
| FR-QA-01 | 判定に必要な情報が不足する場合、判定を保留し、質問する。質問には、どの判定に必要かを併記する |
| FR-QA-02 | 質問は回答形式（数値、文字列、選択）を指定する |
| FR-QA-03 | 回答はセッション内で保持し、同じ質問を繰り返さない |
| FR-QA-04 | 回答は、評価結果の根拠として記録する |
| FR-QA-05 | 回答がない項目は「未確定」と表示する |

初版で用いる質問:

| No. | 質問 | 必要な判定 | 質問する条件 |
|---|---|---|---|
| Q1 | オペアンプの電源電圧（出力の上限の絶対値、V） | 出力の飽和の判定 | オペアンプの出力を解析で使う場合は常に（FR-DR-07） |
| Q2 | 期待値の符号を反転させてよいか | 符号の判定 | 期待値と実測の大きさが一致し、符号だけが異なる場合 |
| Q3 | 期待値の注釈は、仕様か、設計者の目標値か、仮の値か | 期待値の扱い | 注釈に「?」が含まれる、または不確かとして示された場合 |
| Q4 | 解析する周波数（Hz） | 交流の解析 | 交流の信号源があり、C または L を含む場合 |
| Q5 | オペアンプの帯域（GBW） | 帯域による振幅の低下 | 帯域の判定が必要な場合（初版では未実装。後続） |
| Q6 | 出力に接続される負荷 | 出力の振幅・電流 | 負荷の影響が判定に必要な場合（初版では未実装。後続） |

### 5.4 解析（FR-AN）

| ID | 要件 |
|---|---|
| FR-AN-01 | 修正節点解析（MNA）で、直流解析と交流解析（単一周波数の正弦波定常、相量）を行う。入力と出力は実効値で扱う |
| FR-AN-02 | 対象素子は、独立電圧源、独立電流源、抵抗 R、キャパシタ C とインダクタ L（交流解析でのみ）、理想オペアンプ、接地とする |
| FR-AN-03 | 節点電圧、枝電流、各素子の電圧・電流・消費電力を求める |
| FR-AN-04 | 素子の開放、短絡、値の変更を指定して、再解析できる（FMEA と FTA で使用） |
| FR-AN-05 | 対象外の素子が入力された場合は解析せず、その旨を表示し、扱い方を質問する |
| FR-AN-06 | 浮遊節点、直流経路のない節点、行列の特異などで解析できない場合は、原因の節点・素子を示して質問する |
| FR-AN-07 | 解析する節点数の上限は 50 とする。実測の結果により見直す |
| FR-AN-08 | 各オペアンプについて、出力から反転入力への帰還経路（そのオペアンプ自身を除く）を検査する。経路がなければ解析せず、「理想モデルの前提（負帰還）が成り立たない」と報告し、扱いを質問する。理由: 負帰還がない場合、理想モデルでは出力が決まらないため |

### 5.5 観点の選択と設計レビュー（FR-FL、FR-DR）

| ID | 要件 |
|---|---|
| FR-FL-01 | 確定後、利用者は観点（設計レビュー、FMEA、FTA）を選ぶ |
| FR-FL-02 | 観点の連続実行と、途中からのやり直しができる |
| FR-FL-03 | 途中で中断しても、入力と回答は保持される（FR-ST） |
| FR-DR-01 | 期待動作（注釈と期待値）と解析結果を比較し、不一致の箇所を理由とともに提示する |
| FR-DR-02 | 判定の許容誤差は既定で ±5%（相対誤差: 実測と期待の差の絶対値 ÷ 期待の絶対値）とする。注釈に許容差があれば、それを優先する。期待値が 0 の場合は絶対値で判定し、既定は 1 mV（実効値）とする。判定結果には、使った値と出所（既定、注釈、利用者指定）を記録し、評価ごとに変更できる |
| FR-DR-03 | 修正案は複数提示できる。各案について、修正後の再解析結果を示す |
| FR-DR-04 | 修正の可否を利用者に問い、指示に従う |
| FR-DR-05 | 回路図（ネットリスト）を書き換えられる。書き換え後の回路図は、ネットリスト（JSON）で出力する。画像での出力は後続とする |
| FR-DR-06 | 変更の取り消し（Undo）と変更履歴を持つ |
| FR-DR-07 | オペアンプの出力が電源電圧で飽和するかは、Q1 の回答で判定する。観点（設計レビュー、FMEA、FTA）によらず、解析でオペアンプの出力を使う場合は Q1 を常に質問する。回答がない間は「飽和: 未確定」と表示する。理由: 理想モデルでは飽和を判定できないため |

### 5.6 FMEA（FR-FM）

| ID | 要件 |
|---|---|
| FR-FM-01 | 対象部品を利用者が指定する。複数指定できる |
| FR-FM-02 | 指定部品の故障モードを、部品種別のライブラリから一覧表示する。LLM は使わない。理由: 同じ入力から同じ結果を得るため |
| FR-FM-03 | 注入の既定値は利用者が変更できる。変更値は記録する |
| FR-FM-04 | 故障を注入して再解析し、期待値との差で故障の影響を求める。回路全体への影響を見る |
| FR-FM-05 | S（重大度）、O（発生度）、D（検出度）を 1〜10 で評価し、RPN = S × O × D とする。S と D は解析結果から決める。O は利用者が部品ごとに 1〜10 で指定し、根拠を記録する。一括指定はしない |
| FR-FM-06 | 対策要否は、RPN ≥ 100 または S ≥ 9 を既定とし、利用者が変更できる |
| FR-FM-07 | 結果を表（画面表示と CSV）で出力する。表計算ソフトの形式（Excel）は初版の対象外 |

故障モードライブラリ（初版）:

| 部品種別 | 故障モード | 注入方法（既定値） |
|---|---|---|
| 抵抗 R | 開放、短絡、値の変化 | 開放は素子を取り除く。短絡は小抵抗（1 mΩ）で代用。値の変化は ±50% |
| キャパシタ C | 開放、短絡、値の変化 | 同上 |
| インダクタ L | 開放、短絡、値の変化 | 同上 |
| 独立電圧源 | 出力喪失、値の変化 | 出力喪失は 0 V。値の変化は ±10% |
| 独立電流源 | 出力喪失、値の変化 | 出力喪失は 0 A。値の変化は ±10% |
| 理想オペアンプ | 出力喪失 | 出力を 0 V に固定する。飽和とオフセットは対象外 |

ライブラリにない部品種別は「未定義」とし、利用者に故障モードを質問する。

尺度の既定の決め方:

| 指標 | 既定の決め方 |
|---|---|
| S（重大度） | 逸脱が許容誤差以内なら 1。許容誤差を超えるが機能は保たれるなら 4〜6（逸脱量が大きいほど高い）。出力が得られないなら 7〜8。安全関連として指定された機能に影響するなら 9〜10 |
| O（発生度） | 利用者が 1（ほぼ起こらない）〜10（ほぼ確実）で指定する。故障率のデータがないため、根拠を記録する |
| D（検出度） | 期待値のある出力で逸脱が許容誤差を超えるなら 3。許容誤差以内で内部ノードのみ変化するなら 7。変化しないなら 10（潜在故障） |

- 期待値の注釈がない場合は、出力ノードの変化量で判定する。
- 検出判定の許容誤差は、設計レビュー（FR-DR-02）と同じ値を使う。

### 5.7 FTA（FR-FT）

| ID | 要件 |
|---|---|
| FR-FT-01 | トップ事象の候補を、期待値の注釈から生成し、利用者が選ぶ（例: 出力が期待値から許容誤差を超えて外れる） |
| FR-FT-02 | 基本事象は、指定部品の故障モード（ライブラリ）とする。同一部品の同時故障は扱わない |
| FR-FT-03 | 故障の組合せを解析で試し、トップ事象を起こす最小カットセットを求める。組合せの次数は初版では既定を 2 とし、利用者が 3 まで変更できる。組合せ数が多い場合は警告を出す |
| FR-FT-04 | FTA の木構造は、最小カットセットから組み立てる（カットセットどうしは OR、カットセット内の事象は AND） |
| FR-FT-05 | 定量化（確率計算）は初版では行わない。故障率が入力された場合のみ、後続で発生確率を計算する |
| FR-FT-06 | 出力は、FTA 図（SVG）とカットセット一覧（表）とする。各カットセットには、トップ事象を起こす際の逸脱量と根拠を記録する |

### 5.8 結果の表示と記録（FR-RS）

| ID | 要件 |
|---|---|
| FR-RS-01 | 指摘箇所は、画像上に重ねて表示する（部品・ノード単位） |
| FR-RS-02 | 評価結果には、確定したネットリストの版、使用した前提（質問への回答を含む）、許容誤差とその出所、判定根拠を記録する |
| FR-RS-03 | PDF、Markdown などの出力形式は後続とする。初版は画面と CSV で出力する |

### 5.9 途中保存（FR-ST）

| ID | 要件 |
|---|---|
| FR-ST-01 | 作業中の内容（画像、確認画面の編集内容、回答、評価の設定）を、変更のたびにブラウザ内に自動退避する。保持は最新 1 件のみ。次回起動時に復元を提示する |
| FR-ST-02 | ブラウザのデータを消去すると、退避データは失われることを画面に明記する |
| FR-ST-03 | 「保存」でプロジェクトファイル（JSON）をダウンロードし、「開く」で読み込んで再開する。画像は JSON に埋め込む。ファイル形式のバージョンを含める。評価結果は保存せず、評価の設定（FMEA・FTA の対象部品、発生度 O、トップ事象）と回答から再計算する。理由: 同じ入力から同じ結果になるため、保存した結果と食い違わない |
| FR-ST-04 | 外部の API の鍵は、保存・退避のどちらにも含めない |

### 5.10 対話の流れ（FR-FL）

1. 回路を入力する（画像の入力、または手入力）
2. 確認・修正し、確定する
3. 観点を選ぶ（設計レビュー、FMEA、FTA）
4. 不足している情報の質問に答える
5. 観点ごとの結果を表示する（指摘箇所は画像上に表示）
6. 修正案や部品の指定などの指示を出す

## 6. 非機能要件

| ID | 要件 |
|---|---|
| NFR-SEC-01 | アプリは外部 API の鍵やログイン情報を保持、入力、送信しない。外部 LLM は、利用者本人のサブスクリプションによる Claude Code でのみ利用する（FR-EX-01）。回路図は外部送信の対象になり得るため、送信の前に利用者が承認する |
| NFR-SEC-02 | 保存ファイルの管理は利用者の責任とし、画面で注意を表示する |
| NFR-LANG-01 | UI は日本語とする。英語対応は後続とする |
| NFR-DISC-01 | 評価結果は設計支援であり、安全認証や規格適合の判定ではない旨を画面に表示する（REQ-P-04） |
| NFR-LOG-01 | 解析の経過と質問・回答を記録する。保存先はブラウザ内の画面表示と JSON 保存とし、外部には保存しない |
| NFR-PERF-01 | 1 回の評価の目標時間は 10 秒以内とし、部品数の上限は 50 とする。実測により見直す |
| NFR-BR-01 | 対応ブラウザは最新の Chrome と Edge とする |
| NFR-ACC-01 | 検出率・誤検出率の数値目標は設けない |

## 7. 制約

| ID | 制約 | 理由 |
|---|---|---|
| CON-01 | GUI は React で実装する | 利用者の要求 |
| CON-02 | バックエンドを持たない。解析と保存はブラウザ内で行う | 運用と構成を単純にするため |
| CON-03 | 解析は、ブラウザ内で動く修正節点解析（MNA）で行う | CON-02 による |
| CON-04 | オペアンプは理想モデルで扱う | 画像から得られる情報で判定できる範囲に限るため |
| CON-05 | FMEA の故障モードは部品種別のライブラリを正とし、LLM を使わない | 再現性のため |
| CON-06 | フロントエンドは React + TypeScript + Vite とする | 型による誤りの早期発見と、開発の効率のため |
| CON-07 | 外部 LLM は、利用者本人のサブスクリプションによる Claude Code でのみ利用する。アプリは外部 API を呼ばず、API キーとログイン情報を持たない | サードパーティのアプリが、サブスクリプションのログインを使うことは規約で禁止されているため |
## 8. テスト・受け入れ基準

| ID | 受け入れ基準 |
|---|---|
| AC-01 | 期待値と解析結果の逸脱が許容誤差を超える回路で、不一致を検出し、理由を提示する |
| AC-02 | 判定に必要な質問を提示し、回答を待つ。オペアンプの出力を使う場合は Q1 を常に提示する |
| AC-03 | 不一致の期待値に対し、修正案を提示する。各案について、修正後の再解析結果を示す。値の修正案は、再解析で期待値の許容誤差以内に収まることを示す（符号の反転は Q2 に従う） |
| AC-04 | FMEA で部品を指定すると、その部品種別の故障モード（開放、短絡、値の変化など）を一覧表示する |
| AC-05 | FTA で、期待値の逸脱をトップ事象の候補として提示し、最小カットセットを表示する |
| AC-06 | 確定後に編集すると、既存の評価結果が無効になり、再評価を求める |
| AC-07 | 変更後に画面を閉じて再度開くと、自動退避データの復元を提示する |
| AC-08 | 評価結果の画面に免責の表示がある |

テストには、正解が分かっている回路を用いる。要件ごとに、正解のあるテスト回路を最低 1 件ずつ用意する。
